# App shell

`src/ui` is the React app around the [[core]]: a full-viewport dotted canvas with floating islands, following the [[design]] language. It never computes prompt text itself; it calls `buildPrompt(appState(cfg))`.

The prompt is compiled from a `useDeferredValue` copy of the config, and the stage editor's unsaved-changes YAML from a deferred workflow, so typing stays responsive on large workflows. Copy and Export compile the latest config directly if the deferred one has not caught up.

## State

One reducer holds the Python app's `AppConfig` plus an undo history of snapshots, so every edit path is a pure, testable action.

- [[src/ui/state/store.ts#reducer]] records each edit, merges edits of one field within [[src/ui/state/store.ts#COALESCE_MS]] (typing) into one undo step, keeps up to [[src/ui/state/store.ts#HISTORY_LIMIT]] snapshots, and keeps the theme out of history. [[src/ui/state/store.ts#useStore]] wraps it for React.
- Reset follows the Python app: it clears the task, notes and every rail setting but keeps the workflow.
- On the Stages tab the workspace controls show the workflow's pins, and editing a pinned key edits the pin (a blank base removes it), as the Python app's `_pin` does.
- Deliberate difference: The Python app's `show_pinned` copies the pins into the rail's own branch, worktree, commit and base, so they stick after returning to the Task tab. Here [[src/ui/state/store.ts#effectiveWorkspace]] only displays them, so the Task tab keeps its own values and its prompt can differ from the Python app's after a Stages visit.

## Islands

Each island owns one job and reads its commands from the action registry.

- **Main menu** (top-left, labelled "Menu"): Open, Save settings (JSON), Export workflow (YAML), Export prompt (Markdown), palette, shortcuts, welcome hints, the intro video, Star on GitHub (the repository in a new tab, also in the palette, so it stays reachable when the corner ribbon has no room), Reset, and the Light / Dark / System switch. On a phone it also leads with Undo and Redo, which have no floating island there. An open menu lifts its island region to the popover layer, so it drops over phone sheets too, and it scrolls rather than run past the screen's foot.
- **Toolbar** (top-centre): modes `1` Simple task and `2` Stages, panel toggles `3` Settings and `4` Prompt, then Search (the command palette, its ⌘K / Ctrl+K chord in a badge like its neighbours' keys) and Copy prompt, the app's one primary action: a solid accent button always at the right end (on phones too, as the tab bar's one filled tab), so showing or hiding the Prompt panel never changes the toolbar's width. After a successful copy it reads "Copied" with a tick for 1.6 s (its label always keeps room for the longer "Copy prompt", so the toolbar still never changes width), beside the Prompt panel's meta line (the copy toast itself is read out to screen readers only). The Prompt panel has no Copy of its own. Every tool is a [[src/ui/components/ToolButton.tsx#ToolButton]]: icon, a word (the action's `short` label, or its shorter `phone` label on the phone tab bar, so Simple task reads Task there and the bar keeps its width), its key in a 12px badge, and a tooltip with the full name, shortcut and the action's `hint`. In the top toolbar the mode and panel keys are a faint digit with no chip at rest and take their chip on hover or keyboard focus (keeping their room, so nothing shifts); Search keeps its ⌘K chip. The two modes form a segmented control whose current mode is a solid accent pill; the panel toggles are buttons whose glyph says what the panel holds rather than where it docks (`settingsPanel`, a set of sliders, for Settings; `promptPanel`, a page of text, for Prompt), and while a panel shows its button takes a pale accent tint with accent words and the glyph's knobs or page filled, so a shown panel reads as a pressed button and never as a second selected mode (on phones, where the toolbar is a tab bar, the icon returns and a shown panel is marked like a tab, accent words over a short accent bar and no fill, while the mode segments keep 10px inside their pill). A tooltip opens below its button, except on a button in the lower part of the window (the stage bar, the zoom and history row, Help), where it opens above, and near a side edge it lines up with that edge instead of centring past it (App sets `data-tip-pos` / `data-tip-align` as the pointer or focus arrives). It shows on hover, or on focus only while travelling by keyboard (Tab or arrows set `data-nav` on the root; a click or Escape clears it), so focus a closing menu hands back shows none. It also hides while its button's menu is open and after a press until the pointer really moves off the button (a dialog or menu opening over it does not count, so closing one never pops the tooltip back up).
- **Stage bar**: on the Stages tab the top stays one toolbar row, as on the Task tab, so the Prompt panel never jumps between tabs. The tool island (Stage, Prompt block, Function, More ▾, Loop and Parallel) sits centred at the foot of the canvas between the zoom row and Help, its menus opening upward, with the status line just above it; the workflow controls (name, File ▾, status) join the Menu button in one top-left island (Menu | name, File ▾, status) wherever the row fits: from 1320px up, where it stops short of the centred toolbar (a long flash ellipses, "unsaved changes" shows as its dot below 1640px, and Menu drops its word below 1400px), and on phones. From 731px to 1319px the row would run under the toolbar, so the workflow island stacks under the menu and left panels (Settings) start one row lower; the stage inspector docks on the right. Fit sits in the zoom island (see [[stages#Islands and menus]]). Greyed-out Loop and Parallel say in their tooltip what they need: a greyed-out tool is `aria-disabled` rather than `disabled`, so it stays focusable and hoverable while a click does nothing, and an island showing a tooltip lifts over the panels beside it so the Prompt panel's fade never cuts it. The inspector's greyed-out Up / Down say why in their title (already first or last). Under 1180px the bar drops its key badges and swaps the direct tools for one Add ▾; from 960px down to the phone layout it moves under the toolbar at the right edge and the panels start below both; every tool keeps its word.
- **Settings** (left, closed on a first visit; the git, worktree, commit and Unity options): laid out like the stage inspector: a sticky title row in the Prompt panel's hand-drawn voice ruled off by a hairline over a body that scrolls on its own, 18px side padding, sections under small all-caps headings ruled apart and 16px between fields, and an island as tall as its content (never taller than the room above the zoom row, ending a clear 2rem above that row); the sections are branch, base branch, worktree, copy-env, commits, Unity (each choice a segmented control: one grey track with the picked option raised on it as an accent tint with bold accent words and a thin accent ring, the same look as the theme switch, so the choice reads at a glance in both themes; branch, worktree and Unity each start on Off (nothing about them in the prompt; Off greys out the base branch and the Unity CLI check), commits read Atomic / Combined / None and Unity Off / Spawn (Android) / Use existing, short enough that every control is one row, with the full wording in the tooltip and accessible name; inputs and selects use the UI font, monospace is kept for the prompt), and the toggle sub-options, each live only when its toggle is on; a greyed-out option says why beside it with a lock and the card it needs ("Needs Superpowers", "Off while Inline agent only is on", from [[src/ui/lib/rules.ts#optionNeeds]]), wired as its accessible description. When its body (or the inspector's) runs past its foot the last visible lines dissolve into the island's foot under a sticky veil, with a soft shade on the bottom edge, so it says there is more; the shade clears and the veil sits over the bottom padding once scrolled to the end. Digit entries accept at most three (minutes) or two (mock count) digits, like the Tk validators, and flag values that fall back to a default. The groups are one component, [[src/ui/components/WorkspaceSettings.tsx#WorkspaceSettings]], shared with the stage inspector: on the Stages tab a workflow with an Intentions block shows them under that block's toggles in a "Workspace & Unity" section, and Settings (`3`) then opens or closes that block's inspector instead of this panel (it reads as on while the inspector shows the block). A workflow without one keeps this panel, whose note suggests adding the block.
- **Prompt** (right): the compiled prompt, shown by default as a formatted **Preview** (a Preview / Markdown switch in the panel head, remembered per browser under `promptdraw:promptView`): `##` headings as small accent caps with space above, `- ` bullets and `1.` steps with hanging markers, `**bold**` and `` `code` `` drawn without their markers, in the UI face at 14px; a line still waiting for text (an empty stage or prompt block) drops its dangling dash and adds an italic "no description yet" / "empty prompt block" on the amber wash. Copy always takes the raw text. A double-click (or Enter) on the Preview switches to **Markdown**, the raw editable text described next, with the caret in it. With section chips (the Python app's section names, except that a one-step workflow's chip says "workflow 1 step" via [[src/ui/lib/chips.ts#chipLabel]]; the name in the core stays byte-identical), light Markdown highlighting (`##` headings tinted, `**bold**` bold with its `**` markers faint, and a stage line's dangling dash when it has no description faint too: the text stays byte-for-byte the Python app's), the lines/words meta line and a character count (Copy is the toolbar's). While the prompt still carries a compiler placeholder for an empty input (`<describe the task here>`, `<describe the goal here>`, found by [[src/ui/lib/gaps.ts#promptGaps]]) a line under the chips says "Task is empty" (a quiet neutral to-do with a pencil, "fill it in to finish the prompt", until a copy is tried with the placeholder still in; from then on in the session it is the amber warning, so a first visit never opens on an error-coloured banner) with a Fill in button that takes you to the Task card or the workflow Goal, and Copy asks first ("Fill in task" or "Copy anyway"), so a newcomer never pastes an empty task unawares. A stage or cancel stage with no description compiles, as in the Python app, to a line that ends on its dash (`1. **Stage 1** — `); the same line flags it ("Stage 1 has no description", "Goal and 2 stage descriptions are empty"), its Fill in opens that stage with the caret in its description, and Copy asks first ("Copy with an empty stage?"). An empty prompt block compiles, as in the Python app, to a bare `**Note:** ` line and is flagged the same way ("A prompt block is empty"; Fill in opens the first empty one with the caret in its text; Copy asks "Copy with an empty prompt block?"). In the preview each such waiting line (an empty stage or prompt block) sits on a soft amber wash, background only, so it reads as "to fill in" rather than as broken markdown. The placeholders and dangling lines themselves stay in the prompt, byte-identical to the Python app. Like the Python app's output box it is editable: Copy and Export take the edited text, Revert drops the edits, and any change to the inputs recompiles the box. It is a [[src/ui/components/HighlightArea.tsx#HighlightArea]]: a transparent textarea over a mirror that draws the highlights. When a change to the inputs (an intention ticked, a setting changed, typing in the task) adds or changes lines, [[src/ui/lib/changedLines.ts#changedLines]] finds them from the lines the old and new prompt share at each end, and the box tints them with a fading accent background (background only, so glyphs never move under the caret) and scrolls the least that brings the first into view; hand edits, pure removals and near-total rewrites (a tab switch) never flash, and typing keeps extending one running flash rather than restarting it. A prompt from another source (its first line, the opening section heading, changed: a tab switch) starts at the top of the box rather than at the old prompt's scroll offset. The meta line under the box is set in the UI face at 13px/600 with tabular figures (it is chrome, not code), and the box's scrollbar is thin and themed.
- **Star ribbon** ([[src/ui/components/GitHubRibbon.tsx#GitHubRibbon]]): a 128px corner square, pointer-transparent but for its band, a link to [[src/ui/lib/ribbon.ts#REPO_URL|the repository]] in a new tab. After every App render, on resize and once fonts load, [[src/ui/lib/ribbon.ts#ribbonEdge]] places it: the window's corner when no island lies under the band there, else just left of the first panel docked from the window's top past the square's foot (How to work, the Prompt panel, the inspector) that leaves the band clear; with no such spot it hides. Short or floating islands (the How to work button, the starters, the tablet stage bar) never anchor it, since the band's cut end would hang in open canvas. Boxes come from layout offsets, so panels mid-animation count where they will rest, and exit ghosts are skipped. On the Stages tab at laptop widths the centred toolbar reaches the right panel, so the ribbon shows there only with no right panel open.
- **Zoom and history** (bottom-left, with tooltips; their icons at 18px with a heavier stroke, the primary ink when enabled and the faint grey when not, so they hold their own beside the labelled tools) and, bottom-right, **Help** then **AI agent** in the corner (both labelled; on phones both live in the menu).
- Dialogs keep their own 20–24px padding over the island's 4px (the shortcuts dialog, confirmations, warnings); the palette keeps a tight frame around its search, and every row keeps a 20px icon slot so the labels share one column; the backdrop dims the board (40% in light, 62% in dark) and softly blurs it, so the board, panels and toolbar fall back behind the dialog. The shortcuts dialog splits its groups, in order, into three columns of about equal height ([[src/ui/components/ShortcutsDialog.tsx#balance]]; wrapping when narrow) under the inspector's small all-caps group headings, and may use the height down to the backdrop's foot, so every group shows at 1440×900 on either tab (the Stages tab lists more keys), and when it must scroll a soft shade at either end says there is more.
- Below 900px the panels float over the canvas and open one at a time; below 730px the toolbar moves to the bottom as a tab bar with the words under the icons and the stage bar sits above it in one row that fits a 360px screen (Add ▾, Loop, Parallel and Fit, words under the icons), while the workflow controls share the Menu island across the top. Help, undo and redo move into the menu and the zoom island goes (the Task page zooms with the browser, the stage canvas with a pinch), so only the tool rows stack at the foot (`--bar-h`). There the panels (and the stage inspector) are opaque full-width bottom sheets reaching the screen edge, scrolling inside, with the tab bar docked over their foot as an opaque full-width strip (its buttons keep their place), so content scrolls under it cleanly; with a sheet open (`data-sheet` on the app) the stage bar docks too, as a second opaque row above the tab bar, so Add, Loop and Parallel stay one tap away while a stage is edited. [[src/ui/stages/useStages.ts#visibleArea]] reads any full-width panel reaching the screen's foot as a sheet trimming the free canvas, so the flow shows above it. A first visit on a phone opens no panel. Tooltips only open on devices that can hover. On touch screens (`pointer: coarse`) the main menu drops its keyboard chords (⌘O, ⌘S…), as the welcome card drops its key chips. On phones a fade from the canvas colour runs across the top under the menu row (`.app::after`, below the islands), so board content scrolling up fades out rather than running into the Menu island.
- Toasts ([[src/ui/components/Toast.tsx#Toast]]) sit centred just above the foot row of islands, the same offset on both tabs, so they never cover the stage tools or a card; a confirmation goes after [[src/ui/components/Toast.tsx#TOAST_MS]], an error after [[src/ui/components/Toast.tsx#TOAST_ERROR_MS]], and any dialog opening drops the toast at once. A successful copy is a quiet toast, read out to screen readers only: the Copy prompt button's "Copied" and the Prompt panel's meta line already confirm it where the eye is, so no box covers the board's cards; a failed copy is a visible error toast.

## Canvas

In Simple task mode the canvas holds the board: the task as a Goal card, then the ticked "How to work" options drawn by the Stages renderer as a flow into the Prompt (the board pans).

The TASK and EXTRA NOTES fields sit at the top of How to work ([[src/ui/components/TaskCanvas.tsx#TaskFields]]), in one card drawn as the Stages Goal card ([[src/ui/stages/SceneView.tsx#CardFrame]]: lavender fill, accent rough outline, the card's rounded corners, measured so they hold at any size), with GOAL · TASK and EXTRA NOTES eyebrows. An empty task carries a small accent "Start here" tag. The board's Goal card shows the task (or "Describe the task"); clicking it, Edit task (`T`) or a prompt gap's Fill in opens How to work if it was closed or covered and puts the caret in the Task field.

### How to work panel

[[src/ui/components/WorkPanel.tsx#WorkPanel]] holds the sixteen toggles as a fixed panel on the Simple task tab: docked on the right at half the window on wide screens (it holds the Task fields too), a pull-up sheet on phones that pulls itself up when the Task field takes focus.

On wide screens it runs the window's full height against the right edge. The toolbar then centres on the canvas left of it (shedding key badges, then words, as room runs short, and holding still when the Prompt panel takes the edge), Help moves beside it, and the welcome's Copy and, on smaller screens, Menu hints step aside. Its × (solid red) closes it, remembered in prefs (`workClosed`); an orange How to work button top right, or the palette's How to work panel command, brings it back. From 731px to 1040px wide, with the panel closed, the toolbar centres between the Menu and that button instead of on the window, dropping its key badges and, below 861px, its words but Copy prompt's, so it never runs under either.

A divider splits the panel: the Task fields above take 40% of its height and the options scroll below. Drag it, move it with the arrow keys (Home and End for 20% and 80%), or double-click it back to 40%; the split is remembered per browser (`promptdraw:workSplit`). On phones the sheet scrolls as one, with no divider. Every part of the panel shares one 12px side inset. On phones it stays a sheet with no ×.

It holds the right edge the way the stage inspector does on Stages: the Prompt panel (toolbar Prompt, `4`, or the board's Prompt node) takes the same place at the same width and hands it back when closed, the panel staying mounted while hidden. The toolbar's Prompt button shows pressed only while the Prompt panel shows; on Stages the remembered Prompt panel behaves as before. On phones the handle sits above the tab bar and steps aside while another sheet is open.

A search field stays at the top of the list: [[src/ui/lib/intentGroups.ts#filterGroups]] keeps the rows whose name, sentence, prompt line or run title hold every word typed, hides empty runs, and says so when nothing matches; Escape clears it.

Rows come in five short runs under small all-caps headings ([[src/ui/lib/intentGroups.ts#INTENT_GROUPS]]: Before starting, Agents, How to build, Checks, Report back; any toggle the groups miss lands in a last "More" run). The grouping is display only: the prompt keeps `TOGGLE_ORDER`. The title carries an "N on" chip, tinted once something is chosen.

Each row is a hand-drawn check box, the option's name and its one plain sentence ([[src/ui/lib/intentSummaries.ts#INTENT_SUMMARY]], display only, never cut; a toggle with none shows its prompt line held to two lines). A chevron opens the exact prompt line in place without ticking it; screen readers get that line as the checkbox's description. A ticked option with settings of its own ([[src/ui/lib/intentGroups.ts#HAS_OPTIONS]]) shows them right under its row ([[src/ui/components/OptionSettings.tsx#OptionSettings]]: models, minutes, counts, the recon agent cap of at most [[src/core/constants.ts#RECON_COUNT_MAX]], the review loop's passes); they fold away while the option is unticked or locked. On the Simple task tab the Settings panel keeps only the workspace groups and a note saying where the option settings went.

A solid red Reset button beside the search (filled with the danger colour, as destructive actions are) asks, then clears the task, notes and every option, the same as Menu → Reset… (one undoable step; the workflow and theme stay).

Some options only make sense on top of another ([[src/ui/lib/rules.ts#TOGGLE_NEEDS]]): Recon needs Multiple workers (the Python app's rule), Basic dashboard needs Progress reports, since the dashboard shows those reports, and Self-loop code review needs Basic code review, which it loops. Inline agent only locks workers and recon. A locked row keeps its words at full contrast and shows the state with a lock chip under its name saying what it needs and a faded check box. Turning Progress reports off turns the dashboard off with it, and Basic code review its loop ([[src/ui/lib/rules.ts#DROPS_WITH]]); recon keeps the Python app's behaviour, staying ticked while the core leaves it out. The dashboard rule is the app's own: the compiled prompt for any given config is unchanged.

### Parallel option lanes

[[src/ui/components/OptionLanes.tsx#OptionLanes]] draws what is ticked with the Stages renderer itself, so cards, frames, read-only stages, model tags and agentic loops look the same on both tabs.

[[src/ui/lib/taskScene.ts#taskScene]] turns the ticked options into a [[src/core/workflow.ts#Workflow]] plus a [[src/core/layout.ts#Layout]] of its own, and [[src/ui/stages/SceneView.tsx#SceneView]] paints it with a [[src/ui/stages/scene.ts#BoardView]]: read-only (no Group ticks or + links), run-name eyebrows, and locked cards, arrows and frames dimmed and dashed, with a padlock and the reason as the card's body. The layout is the board's own because a row may chain or hold a loop, which the Stages flow does not allow inside a parallel group.

[[src/ui/lib/taskScene.ts#boardModel]] builds the rows from [[src/ui/lib/intentGroups.ts#laneRows]] (an option that needs another follows it in its row):

- Recon via workers after Multiple workers becomes a parallel frame of one Recon function block repeated per worker and lettered like parallel branches (Recon A, B, C…): read-only (hatched, eye icon) with the recon model's tag. There is one per the Recon agents cap set under the option (at most five), or [[src/core/constants.ts#RECON_COUNT_DEFAULT]] while it is not set.
- Basic code review with Self-loop code review becomes an agentic loop frame round a read-only Code review function block on [[src/core/constants.ts#REVIEW_MODEL]] (the prompt asks for a fresh opus reviewer each pass) and a Fix findings stage the session runs, its pill reading the reward (until critical & high fixed % ≥ 100, max passes) and the return arrow under them.
- UI intelligence is drawn as the loop its prompt line runs: an agentic loop frame round Screenshot, Analyse, Iterate and Critique stages ([[src/ui/lib/taskScene.ts#UI_LOOP]]), its pill reading "until it meets the goal and looks good" through the board's `loopText`, since that loop stops on a judgement, not a score.
- Every other option is a stage card with its sentence; the flow ends in a PROMPT card that opens the Prompt panel.

All rows sit in one parallel frame, and the flow runs left to right as the Stages flow does: arrows run from the Goal card ([[src/ui/lib/taskScene.ts#GOAL_KEY]]) over a bus inside the frame into each row and out over the other bus into the PROMPT card, all three on one middle line. Each arrow is keyed by its two ends (`edgeKeys`), so its wobble and identity hold as others come and go. What runs past the screen is reached by panning the board. A card's × unticks its option; a visually hidden list gives keyboards and screen readers the same Remove buttons and a Show the prompt button.

### Task board

The Task tab is a whiteboard too: [[src/ui/components/TaskBoard.tsx#TaskBoard]] floats the cards on a world that pans and zooms (50–200%, [[src/ui/lib/board.ts#boardZoom]]) under the islands, using the stage viewport math.

- A plain drag anywhere except a text field pans; a drag that starts on a card or button pans and swallows its click. Space+drag and middle-drag pan from anywhere, including fields.
- Wheel and two-finger scroll pan (a text field that can still scroll keeps the wheel); Ctrl/Cmd+wheel and pinch zoom toward the pointer, about 10% per wheel notch ([[src/ui/stages/viewport.ts#wheelZoom]] caps each event at [[src/ui/stages/viewport.ts#WHEEL_CAP]]); touch pinch zooms around the fingers.
- A click on empty board leaves the field being edited; tabbing to an off-screen field pans it into view.
- [[src/ui/stages/viewport.ts#keepInView]] keeps part of the sheet on screen however far it is flung. The world is padded by the `--pad-*` insets so its home view rests clear of the open panels (and 24px under the toolbar on desktop, so the Task card's frame never meets its shadow), with the sheet centred between the left edge (or the Settings panel) and the Prompt panel, equal gutters on both sides. Inside the sheet the welcome card and the board are centred too: the board while it fits (a longer one starts at the left gutter), and on desktop the welcome card keeps 1.5rem clear of each sheet edge so the Star ribbon beside a docked panel never cuts its corner, dropping its quick actions' key chips when it is short of room (under 44rem); on desktop the board's content is masked out along its foot, dissolving over 3.5rem and gone a few pixels above the bottom island row, so no card text sits half hidden behind the zoom and history islands while the dot grid (on the canvas, not the board) runs on to the edge (the bottom padding lets the last card scroll clear of them); on phones a short fade under the menu row keeps scrolled text from running into it, a matching fade behind the floating tab bar does the same at the foot of the Task page (the bottom padding lets the last card scroll clear of the bar), and touch screens drop the text areas' resize corner.
- The view lives in [[src/ui/lib/useChasedView.ts#useChasedView]]: every pan and zoom (wheel, pinch, drag, the zoom island) sets where the camera is heading and the shown view chases it each frame with the stage canvas's [[src/ui/stages/viewport.ts#chaseView]], so the board glides rather than jumps.
- Only the zoom is remembered (in prefs); resetting zoom also pans home.

In Stages mode the canvas renders [[src/ui/components/StagesMount.tsx#StagesMount]], which hosts the stage editor described in [[stages]].

## Actions and shortcuts

[[src/ui/actions.ts#buildActions]] declares every command once; the toolbar, menu, palette, shortcuts dialog and global key handler ([[src/ui/actions.ts#handleShortcut]]) all read it.

- Bare-key shortcuts never fire while a text field has focus ([[src/ui/lib/keys.ts#isTyping]]), and undo/redo stay native inside fields.
- `Ctrl/Cmd+K` (shown everywhere; plain Ctrl+K works on a Mac too, through a `ctrl` key spec in [[src/ui/lib/keys.ts#matches]]) or `Ctrl/Cmd+/` opens the fuzzy command palette (intention toggles included; with no query, recent commands first, then the current tab's own group via [[src/ui/actions.ts#paletteOrder]] (Stages on the Stages tab, Prompt on the Task tab) so the preselected row is one you can use there; every command carries an icon, and a command that cannot run now, such as Close inspector with nothing open, is left out); `?` opens the shortcuts dialog, which lists bindings that print alike (`⌘=` and `⌘+`) once, the stage keys from either tab (a "Stages tab" group while they are not live) and the canvas gestures, each on one line (drag or Space+drag on empty space to pan, wheel and Shift+wheel to scroll, Ctrl/Cmd+wheel or pinch to zoom, Shift+click to tick, drag a stage onto a gap to reorder). Intention cards carry no digits: they are not shortcuts, and 1–4 already switch modes and panels.
- Other keys: `Ctrl/Cmd+Enter` copy, `Ctrl/Cmd+O` open, `Ctrl/Cmd+S` save settings (on the Stages tab it saves the workflow, like the Python app's Save; `Ctrl/Cmd+Alt+S` saves settings on any tab), `Ctrl/Cmd+Shift+S` export YAML, `Ctrl/Cmd+Shift+E` export prompt, `Ctrl/Cmd+Z` / `Shift+Z` / `Y` undo and redo, `Ctrl/Cmd+=`, `-`, `0` zoom, `Alt+Shift+D` theme, `T` edit task.
- Dialogs trap focus, close on Escape or a backdrop click, and restore focus.

## Persistence and files

The browser keeps the config as the Python app's own `.prompt_builder.json` text, so storage and file export share one format.

- [[src/ui/state/persistence.ts#STORAGE_KEYS]]: `promptdraw:config` holds `serializeAppConfig(cfg)`; `promptdraw:task` the task (the Python app never saved it); `promptdraw:prefs` open panels, zoom and whether the welcome was dismissed (a first visit opens only the Prompt panel, none on a phone: [[src/ui/state/persistence.ts#DEFAULT_PREFS]], [[src/ui/state/persistence.ts#hasPrefs]]); `promptdraw:theme` the theme, applied before first paint by an inline script; `promptdraw:intro` is `seen` once the [[ui#App shell#Intro video]] has been closed.
- Saves are debounced by [[src/ui/state/persistence.ts#SAVE_DEBOUNCE_MS]] (300 ms) and flushed when the tab hides or closes; each save stamps `promptdraw:savedAt` last, later than any stamp already stored.
- [[src/ui/state/persistence.ts#useAutosave]] reacts only to a newer `savedAt` from another tab, skips it while this tab has unsaved edits (they win when they save) and ignores saves whose [[src/ui/state/persistence.ts#sharedContent]] matches. The store takes the rest as one undoable `external` step that keeps this tab's `tab` and `mode`.
- Opening or dropping a file goes through [[src/ui/lib/files.ts#importText]]: a `.json` file loads through `loadAppConfig` (keeping the typed task); a `.yaml` file loads a workflow through `fromYaml`, switches to Stages and lists any load warnings.
- Either kind that would change the workflow first asks to discard unsaved stage edits, then resets the stage editor's saved baseline. A [[ui#App shell#Workflow links|workflow link]] opens the same way.

## Workflow links

A link can carry a workflow, so an agent can hand the user a file plus a link that opens it; the content stays in the URL fragment and never reaches a server.

The shape is `<site>/#wf=<payload>`, with `&check` appended for check mode. [[src/ui/lib/link.ts#encodePayload]] makes the payload: the YAML's UTF-8 bytes, raw DEFLATE, base64url without padding (the same bytes as Node's `zlib.deflateRawSync`). [[src/ui/lib/link.ts#decodePayload]] reverses it and throws [[src/ui/lib/link.ts#LinkError]] for text that isn't base64url, DEFLATE or UTF-8. [[src/ui/lib/link.ts#parseLinkHash]] reads a fragment and [[src/ui/lib/link.ts#buildLink]] writes one against [[src/ui/lib/link.ts#SITE_URL]]; [[src/ui/lib/link.ts#LINK_LIMIT]] (8,000 payload characters) is the most a hand-off shows as a link.

On mount and on `hashchange`, `App` reads a normal `#wf=` link, clears the fragment with `history.replaceState` (a reload doesn't reopen it), decodes it and loads it through [[src/ui/lib/files.ts#importText]] as `link.yaml`. From there it takes the same path as opening a file: unsaved stage edits are guarded, the workflow is replaced, the app switches to Stages and shows the "Loaded with changes" warnings or a "Loaded <name> from link" notice. A link that won't decode or parse shows "Couldn't load workflow from link: <reason>" and changes nothing. The workflow is not saved to the library.

### Check mode

A `&check` link lets an agent check a workflow in any browser, even the user's own profile, without reading or touching their saved work.

[[src/main.tsx]] calls [[src/ui/state/checkMode.ts#initCheckMode]] before the first render. For a check link it swaps `localStorage` for an in-memory [[src/ui/state/checkMode.ts#MemoryStorage]], so the page starts from defaults, every save (autosave, prefs, library, intro) vanishes with the page, and [[src/ui/state/persistence.ts#useAutosave]] skips the `storage` listener so other tabs' saves never reach it. There is no intro video, welcome or discard guard. [[src/ui/components/CheckReport.tsx#CheckReport]] shows "Check mode: nothing is saved" with **Open for real**, which loads the same link without `&check`.

The page loads the link's workflow onto Stages without the discard guard and keeps the fragment, so a reload re-runs the check. Its island prints [[src/ui/lib/check.ts#reportText]] of [[src/ui/lib/check.ts#checkWorkflow]] as plain text in a "Workflow check" region: `Workflow check: PASS` or `FAIL`; `Couldn't load workflow: <reason>` on a parse or link error; otherwise the name and counts (blocks, parallel groups, loops), `Warnings: none` or the load warnings, and `Round trip: identical` or `Round trip: the app would rewrite this file` with the first five differing lines. The round trip compares the file with what `toYaml` writes back, ignoring comment lines and line endings, so a misspelled key the faithful parser skips still fails. Pass means no load error, no warnings and an identical round trip.

The mode is fixed per page load ([[src/ui/state/checkMode.ts#isCheckMode]]): a `hashchange` in a check-mode page, or to a check link in a normal one, reloads the page.

## Tests

Component tests drive the whole app; unit tests cover the pure helpers.

`App.test.tsx` uses Testing Library: toggling an option changes the prompt and draws it on the board through the Stages renderer (a card's × unticks it; the Prompt card opens its panel; recon fans out into lettered read-only Recon function blocks, the self-loop review and UI intelligence each draw an agentic loop, Inline agent only dims and locks workers and recon, unticking the review unticks its loop), the How to work search filter, closing How to work with its × and bringing it back, the Task fields living in How to work with the board's Goal card reopening them, the 40% divider's keyboard moves, Fit on the Simple task zoom island, the Stages tab's Demo workflows opening a starter, a ticked option's settings under its row (the recon agent cap up to five), Reset from the panel after its dialog, copy (and the empty-task flag with its ask-before-copy dialog), the Prompt panel's Preview (no markdown markers, raw Copy, double-click to the remembered Markdown view; the other prompt tests pin the Markdown view), import by file and by drop, the palette, menu, toolbar, dialogs, undo, zoom, persistence across reloads, the welcome hints and the intro video (opens once on a brand-new browser and stays closed after Start drawing or Escape, skips a returning visitor with saved prefs, reopens from the menu; every other suite marks it seen first). Unit tests cover the store, persistence, the prompt placeholder finder, the greyed-out option reasons, file helpers, key matching, the rail rules (Basic dashboard waiting on and going off with Progress reports), the board's option rows (chains in panel order, locks under Inline agent only, a lone locked dependant) and the fuzzy matcher.

### Workflow links open on Stages

A `#wf=` link to a starter opens it on the Stages canvas with a "from link" notice and leaves the address bar without the fragment.

### Workflow links ask before replacing unsaved edits

A link pasted into a tab with unsaved stage edits asks first, and Cancel keeps the old workflow.

### Check mode never touches saved data

With a check link, saved keys stay unread and every write lands in memory only; a normal link leaves the real storage in place.

### Check report passes a canonical workflow

A starter written by `toYaml` checks as PASS with no warnings, an identical round trip and its loop count.

### Check report catches misspelled keys

A stage with `promt:` parses cleanly but fails the round trip, and the report names the differing line.

### Check mode reports on the workflow

A check link opens on Stages with the banner, no intro video, a PASS report, and the fragment kept for a re-check.

### Check mode shows no welcome

A check link that fails to load leaves the page on the Task tab, where the welcome card and arrows still stay hidden, so an agent reads only the report.

### Use with an AI agent

The bottom AI agent button and the main menu item open the agent dialog, whose copy button puts both install commands on the clipboard.

### Broken workflow links change nothing

A payload that isn't base64url reports "Couldn't load workflow from link:" and leaves the app on its old config.

### Settings live in the Intentions block on Stages

On a workflow with an Intentions block, Settings (`3`) opens that block's inspector with the branch, worktree, commit and Unity groups whose edits change the prompt, and the floating panel stays shut; without the block the panel opens.
